# 🐛 Bug Reporting Guide

## What to include
- Affected exercise (Q1-Q5) or documentation path.
- Browser and version.
- Operating system.
- Exact steps to reproduce.
- Expected and actual behavior.
- Sanitized Console error or genuine screenshot.
- Whether the issue occurs after a fresh clone.

## Where to report
Use GitHub Issues for ordinary bugs and documentation corrections. Use the private process in root [SECURITY.md](../SECURITY.md) for vulnerabilities.

## Good reports
A good report isolates one problem and gives enough detail for another person to reproduce it. Avoid posting credentials or personal data.
